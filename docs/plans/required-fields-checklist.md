# Required fields checklist (proposed, 10 Nov 2026)

What a syllabus must say before it can be submitted for review. Every course, Foundation Year
included, uses the SCEN syllabus template since 10 Nov 2026, so there is one list. "Required" rows are what
`backend/sorbonne/services/syllabus_completeness.py` checks; "optional" rows are never checked.
Saving and exporting a draft are never blocked. Christian ticks the online copy of this list;
his choices are applied here and in the rules.

## All courses

### 1. Course identification

- [x] Course code: Names the course in the library, the document and the export file.
- [x] Course title: Printed at the top of the document.
- [x] Academic year: Tells this year's syllabus from last year's.
- [ ] Course, from Students and Timetables: A shortcut that fills code, title, ECTS and semester.
- [x] Degree level and semester: Printed in the identification table.
- [x] Programme: Already required on screen since this round. It decides which PLOs a CLO can be aligned to.
- [x] Number of ECTS: Printed in the identification table.
- [x] Contact hours (lectures, tutorials, workshops, seminars, laboratory, other) (at least one type): A course with no hours at all is unfinished.
- [ ] Prerequisites: Many courses have none.
- [ ] Co-requisites: Most courses have none.
- [ ] Equipment: Most courses need none.

### 2. Academic contacts

- [x] Instructor's name (typed, or chosen from People) (first instructor): Students need to know who teaches the course.
- [x] Instructor's email (first instructor): Students need a way to reach the instructor.
- [ ] Academic rank / status: Comes from People when the instructor is chosen there.
- [ ] Affiliations
- [ ] Office hours and location: Could be required; many teachers set them only once the timetable is out.
- [ ] More instructors
- [x] Academic coordinator: The drop-down from this round; the document names the coordinator.

### 3. Course description and delivery

- [x] Course description
- [x] Delivery mode
- [x] Face-to-face and online shares (Blended delivery only; they must add up to 100%)

### 4. Learning outcomes

- [x] At least one CLO, each one written (Teacher mode)
- [x] Each CLO aligned to at least one PLO (Teacher mode, when the programme has PLOs): Only the PLOs the curriculum mapping expects of the course are offered. The Foundation Year programme has none, so its courses are not asked.
- [x] Every PLO the curriculum mapping expects is aligned at least once (Teacher mode, when the mapping lists the course): Your rule from this round.
- [ ] SCEN graduate competencies of each CLO (Teacher mode)
- [x] The Head of Department has written the course's CLOs (Head of Department mode): The teacher cannot submit until the course has its CLOs in the curriculum mapping.

### 5. Course schedule: sessions

- [x] At least one session
- [x] Topic of each session
- [x] Week of each session: The week is what orders the schedule and places graded activities.
- [ ] Session type (CM, TD, TP): Always set: new sessions start as CM.
- [ ] Session details
- [ ] Pre-class learning activities (name to be decided)
- [x] Earlier notes moved into graded activities or cleared (converted syllabi): Text from the old Assessments and Deadline columns, kept for the teacher to deal with.

### 5. Course schedule: graded activities

- [x] At least one graded activity
- [x] Week: Places the activity in the schedule.
- [ ] Assessment date: You chose week required, date optional.
- [x] Assessment type: Decides which grading rubric is shown.
- [ ] Name for this activity: The type is used when there is no name.
- [x] Weight, with all weights adding up to 100%
- [x] CLOs assessed
- [x] Applicable AI policy: One of the template's five options.
- [x] The teacher's own description of the AI policy (when "Other (Specify)" is chosen)

### 6. Bibliography

- [ ] Books, websites and journal articles: Could be "at least one reference".

### 7. Teaching approach

- [x] At least one teaching and learning approach: Fills the methods, engagement and feedback wording.

### 8. Course assessment

- [x] Assessment methodologies
- [x] Late submission policy
- [x] How AI use is checked (verification mechanism) (when an activity uses "AI Prohibited")
- [x] Permitted uses of AI (at least one) (when an activity uses "AI Permitted as a Support Tool")
- [ ] Additional instructions regarding AI: Aude's options are still to come.
